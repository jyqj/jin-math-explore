# Project core cognition v13

`math-research-project-core-cognition/v1` is the immutable project-wide understanding frozen for one attempt inside a window. It answers: what the objective is, what the window's source map had strictly established, where the real bottleneck comes from, why this attempt's route is chosen now, what the evidence does not support, and when details must be retrieved.

Generate it after validating the window's frozen official-map v1 snapshot, authoritative v2 route review, route portfolio member, and attempt-local route decision. Bind the project ID, objective hash, window ID, source project head/map, map validation receipt, route review, route decision, selected route card, and every source reference. All sibling attempts bind the same source map/head but receive distinct decision/cognition hashes and cannot consume one another's unverified staging. Keep canonical JSON near or below the 24 KiB operating target, but treat excess as maintenance rather than an activation failure. The JSON is a semantic source, not the text injected into the model; always render and count the final Markdown reading layer before `ATTEMPT_START`.

Required sections are: objective; method orientation; verified method spine; current bottleneck and its derivation; route decision with `why_now` and comparison to alternatives; evidence boundaries; retrieval triggers; semantic reset conditions; and freeze policy. Every verified-method and route-decision claim needs an authoritative reference. State explicitly when a proposed proof object, matrix, computation, or certificate has not been instantiated.

Method orientation comes before technical steps. State the method family, the prior or public baseline being extended, the project's high-level modification, and the mechanism connecting that modification to the result. Define every central proof object and every nonstandard parameter used in the cognition: what the symbol means, its frozen value, why that value or relation was chosen, and its source. Never begin with an unexplained tuple such as `K=...` or `(a,b,c)=...`; a reader returning months later must understand the conceptual picture before seeing the proof chain.

The cognition is immutable for the attempt. A checkpoint may replace only the continuity capsule, which records changing local position, newly opened local questions, and the last verified checkpoint. Context restoration injects the identical cognition bytes plus the latest valid capsule. Any change to the objective, proof object, mechanism, quantifier strategy, evidence standard, selected route, or causal interpretation requires semantic reset and `ATTEMPT_END`; the current window does not auto-create a successor. A later window decides whether to repair, reopen, or choose another route.

## Bounded reading layers without unattended interruption

Research history may grow without bound; project-core cognition must not become a chronological append-only summary. Generate it from the frozen window source map for every attempt. Retain the exact objective, method family and modification, verified method spine and reusable structures, derived bottleneck, route-selection causality, alternative comparison, success and candidate-failure gates, uninstantiated objects, evidence scopes and non-implications, retrieval triggers, and semantic-reset conditions. Move proof details, old candidate enumerations, raw calculations, repeated formulas, and route chronology behind stable map or evidence references.

Before a long unattended attempt, prepare all three renderer profiles from the same validated JSON:

- `normal`: readable project-wide cognition, with a 7,000-token operating target;
- `compact`: the same required semantics with duplication and historical explanation removed;
- `minimal_safe`: the same objective, causal method spine, bottleneck, route decision, evidence boundary, retrieval, and reset semantics in the smallest form.

Count the complete rendered Markdown, not the JSON or an estimate of its prose. Prefer exact `o200k_base`; when that local tokenizer is unavailable, use the UTF-8 byte count as a conservative BPE upper bound and record the counting quality. Freeze `math-research-cognition-budget/v1`, the selected profile, selected rendering hash, and token count. Select normal at or below 7,000 tokens, otherwise compact at or below 8,192, otherwise minimal-safe at or below 8,192. If even minimal-safe exceeds 8,192, select it anyway, set `budget_status=exceeded` and `maintenance_due=true`, and continue. Token excess is an efficiency/maintenance condition: it must never block, pause, fail, reroute, or request user presence during an authorized attempt.

Do not truncate by token position and do not let a model freely choose omissions. Never remove the objective, method-to-result mechanism, bottleneck derivation, `why_now`, comparison to alternatives, evidence non-implications, uninstantiated-object warning, retrieval triggers, or reset conditions. Only target, evidence, binding, or route-integrity failures may block activation. During restoration inject the exact selected rendering bytes plus the latest capsule; a checkpoint cannot replace either the cognition JSON or selected rendering hash.

Use `scripts/project_core_cognition_v13.py generate|validate|render|prepare-budget|validate-budget`. A cognition delivered to a user must come from this sequence; do not hand-compose a look-alike Markdown. For a legacy read-only rehearsal, validate without the activation flag, preserve available legacy bindings, use `null` for an asset that does not exist, and list it in `missing_activation_bindings`; never invent a route-card or review hash. For a real attempt, validate with activation. Validation checks schema, closed fields, hashes, authoritative references, official map v1 activation eligibility, route-review v2 binding, selected-route consistency, reports canonical size, verifies all three render hashes, and enforces the nonblocking budget policy. It cannot prove that prose is mathematically correct; independent semantic review remains mandatory.
