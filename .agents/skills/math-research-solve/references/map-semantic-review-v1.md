# Map semantic review v1

`map_semantic_review` is the independent publication gate for every new or changed official research map. It does not change the `math-research-project/v13` or `math-research-map/v1` version axes. Structural validation proves shape; this protocol decides whether the exact map is a complete, evidence-bounded, project-wide synthesis. A string such as `semantic_review=PASS`, a nonempty pointer, or `{"verdict":"PASS"}` is never a receipt.

## Non-bypassable workflow

The map author freezes the candidate, complete authority inventory, candidate authority manifest, visible-tree inventory, protocol bytes, and structural validation receipt. Run `scripts/map_semantic_review_v1.py prepare` to create one packet and one ticket for cycle 1, 2, or 3. The Host then calls `spawn_agent` with `fork_turns="none"` and gives that subagent only the frozen packet and ticket. The reviewer principal must be different from the author and every earlier reviewer, must declare `fresh_subagent`, and must not have drafted, edited, repaired, or selected the candidate.

The reviewer writes only a closed result. Run `validate-result` before accepting it. `PASS` is legal only when every authority item and all eight synthesis roles pass and both `repairs` and `unresolved` are empty. `FAIL` and `INCONCLUSIVE` are non-publication outcomes. A `FAIL` requires the original author to change the candidate bytes against the immutable findings before issuing a new packet and ticket. An `INCONCLUSIVE` may instead keep the candidate bytes unchanged only when the Host binds a new retrieval request and nonempty bounded evidence slices that answer the prior review; it still requires a new packet, ticket, and reviewer. Every earlier review remains bound only to its exact packet and cannot authorize the later round. `finalize` accepts at most three linked rounds and creates a closure only when the final result is PASS on the exact final candidate. `validate-closure` rehashes all bindings before Startup or publication.

If three rounds do not produce PASS, or if a fresh subagent cannot be dispatched, keep the old research authority current and open the existing owner-scoped `review_required` gate through `WINDOW_RECONCILIATION_FAIL` or `MAINTENANCE_FAIL`. A later invocation may begin another bounded review cycle, but no failed cycle counts as a successful map update. There is no `single_agent_fallback` for this gate.

## Closed artifacts

All four artifacts use strict JSON: duplicate, missing, or unknown fields fail closed.

### `math-research-map-review-packet/v1`

Its exact top-level fields are `schema, protocol, project, candidate, authority, structural_validation, evidence_boundary`. `project` binds `project_id` and `project_objective_sha256`. `protocol` binds its relative path, content and SHA-256. `candidate` binds the map-control path, byte and semantic hashes, control object, complete visible-tree inventory and hash, and inventory-bound candidate documents. Candidate documents are the visible Markdown plus every hash-bound `terminal_sufficient_condition_register`, when present; they do not invent separate map-root or main-map hash fields. `authority` binds the normalized source head, candidate manifest, complete authority inventory and their paths/hashes. The normalized head excludes the self-referential `independent_semantic_review` field before hashing. Every `authority.entries` row has exactly `authority_id, kind, sha256, summary`; together they enumerate every promoted memory item, route review and route record needed for history, standalone result, milestone, prior map node, affected evidence summary, and migration source when applicable. `structural_validation` binds the exact PASS receipt, and `evidence_boundary` records the fixed allowed/excluded categories, retrieval-request hash and any Host-approved evidence slices.

### `math-research-map-review-ticket/v1`

Its exact top-level fields are `schema, ticket_id, packet_sha256, protocol_sha256, project_id, candidate_map_sha256, visible_tree_inventory_sha256, authority_manifest_sha256, authority_inventory_sha256, structural_receipt_sha256, author_principal, reviewer_principal, reviewer_mode, dispatch_id, cycle, max_cycles, prior_result_sha256, repair_lineage, result_contract_sha256, retrieval_request_sha256`. `reviewer_mode` must be `fresh_subagent`, `max_cycles` must be `3`, and `result_contract_sha256` closes the reviewer output schema. The ticket forbids candidate writes and all unlisted retrieval. A reviewer principal is unique within the lineage; author/reviewer equality, repeated reviewer identity, missing dispatch binding, or a nonblank inherited context fails closed.

`packet_sha256` is the protocol document digest, computed from recursively key-sorted compact UTF-8 JSON plus one final LF. It is not the raw file-byte digest unless those byte representations happen to coincide. Before reviewer dispatch, run `scripts/window_authoring_preflight_v13.py review-digests`; it reports the document and raw digests under distinct names and fails only when the ticket is not bound to the document digest.

### `math-research-map-review-result/v1`

Its exact top-level fields are `schema, ticket_id, packet_sha256, protocol_sha256, project_id, candidate_map_sha256, visible_tree_inventory_sha256, authority_manifest_sha256, authority_inventory_sha256, structural_receipt_sha256, reviewer_principal, reviewer_mode, dispatch_id, cycle, authority_coverage, synthesis_checks, evidence_boundary, verdict, repairs, unresolved`. The result repeats the ticket's exact bindings and `reviewer_mode=fresh_subagent`. Every `authority_coverage` row has exactly `authority_id, verdict, rationale`, covers one packet authority exactly once, and uses verdict `PASS|FAIL|INCONCLUSIVE`. Every `synthesis_checks` row has exactly `role, verdict, rationale`, uses verdict `PASS|FAIL|INCONCLUSIVE`, and covers exactly once each of `objective-context`, `unified-method-spine`, `historical-development`, `route-genealogy`, `cross-route-structure`, `global-state`, `frontier`, and `authority-coverage`. Result `evidence_boundary` has exactly `classification, categories_seen, retrieval_requests`; `classification` is `minimized-remote`, `categories_seen` is a list drawn only from packet-allowed categories, and `retrieval_requests` is a list. Top-level `verdict` is `PASS|FAIL|INCONCLUSIVE`; `repairs` and `unresolved` are lists whose every member is a nonempty string. A reviewer may request more evidence but may not retrieve it directly or modify the map.

### `math-research-map-review-closure/v1`

Its exact top-level fields are `schema, protocol_sha256, project_id, project_objective_sha256, author_principal, bindings, rounds, repair_lineage, final_pass, status`. `bindings` names the protocol, map control, normalized authority head source, authority manifest, authority inventory and structural receipt. Each of the ordered one-to-three `rounds` embeds its exact packet, ticket and result plus their hashes, candidate/inventory/receipt hashes, distinct reviewer identity, verdict and counts. After a non-PASS round, `repair_lineage` binds the prior result and the SHA-256 of its `repairs`/`unresolved` set to adjacent candidate-map hashes and a repair summary. A prior `FAIL` requires different adjacent candidate hashes. A prior `INCONCLUSIVE` may keep them equal only when the next ticket and packet bind a new retrieval request with nonempty bounded evidence slices. `final_pass` repeats the exact final-round binding, and `status` is PASS. A missing lineage link, stale hash, repeated reviewer, non-PASS final result, or any PASS containing repairs or unresolved items invalidates the closure.

## Eight semantic checks

The reviewer checks the same eight roles that the structural validator locates, but semantically:

1. `objective-context`: exact objective, objects, quantifiers, and terminal gap are taught without drift.
2. `unified-method-spine`: dependencies and proof obligations form a truthful mathematical spine rather than a file list.
3. `historical-development`: decisive evidence and belief-changing turns are reconstructed without hindsight invention.
4. `route-genealogy`: routes are correctly classified by proof object, mechanism, quantifier strategy, dependencies, gates, and failure scope; equivalence is not asserted without evidence.
5. `cross-route-structure`: shared reductions, invariants, obstructions, dualities, or absences are evidence-backed and distinctions are preserved. For a registered sufficient-condition topic, this includes the complete implication/equivalence/incomparability structure, a visible route-local terminal proposition for every expandable branch, one sufficient shared definition card, a separately titled `proposition` callout for every registered condition, and the named evidence basis for an honest difficulty partial order; route maturity alone is not proposition difficulty.
6. `global-state`: proved, bounded, refuted, blocked, and unknown claims keep their exact evidence grades and scopes.
7. `frontier`: missing bridges and coverage gaps are explicit without smuggling in a next-route decision. For a registered sufficient-condition topic, every listed proposition is terminal under its declared implication path. Judge self-containment on the portable unit consisting of the exact shared definition card plus the selected proposition callout: the card defines or quantifies every reused object and standing convention, while the proposition retains every route-specific hypothesis and writes the final objective conclusion explicitly. A short proposition may say “沿用本专题共享定义” or its language equivalent, but may not rely on an undefined register ID, an unbound external note, or context-only phrases such as “existing/current/original route.” Conjunctive premises are not miscounted as separate terminal propositions, an intermediate success gate is expanded to the full route-local closure rather than substituted for it, material near-misses appear as exclusions, and criterion-layer propositions receive an explicit difficulty disposition. For every exclusion, verify which local candidate or intermediate condition fails, whether the complete route remains, and that the prose does not inflate local insufficiency into whole-route rejection. If the object class itself cannot yet be stated precisely, label the box as a research-target template rather than certifying it as a complete proposition.
8. `authority-coverage`: every inventoried memory, route, route review, success gate, result, milestone, prior node, affected evidence record, and migration source is integrated or explicitly justified as non-global. For a sufficient-condition topic, compare each material candidate source with `candidate_source_coverage`, follow the visible route, evidence, exact-boundary and terminal-proposition links, and verify that the linked material actually supports the registered disposition. Fail if a route-local or intermediate sufficient proposition was silently compressed into a broader criterion or omitted.

## Minimal reviewer context

The reviewer receives only the frozen packet and ticket. This is `minimized-remote`: do not include the whole project, raw object bodies, import bodies, recovery trees, journals, logs, unrelated notes, previous reviewer prose, expected errors, proposed fixes, or the author's hidden reasoning. Hashes and bounded evidence summaries establish completeness without bulk disclosure.

If a coverage row cannot be judged, the reviewer returns `INCONCLUSIVE` plus a precise retrieval request naming the authority item, mathematical question, and smallest evidence slice needed. The Host may add only that slice, record its provenance and category, and issue a new packet and ticket. A retrieval request never grants the reviewer direct filesystem access and never permits appending material to an already reviewed packet.

## Publication and legacy policy

`semantic_review_receipt` must resolve to a valid closure over the exact candidate publication. The commit Harness independently recomputes candidate-map and visible-tree hashes, inventories, manifest, protocol and structural-receipt hashes, principal separation, lineage, repair mappings, complete coverage, eight checks, and the final PASS. Any byte change invalidates the closure.

Reuse the existing v13 lifecycle; this protocol adds no parallel state. `WINDOW_RECONCILE`, `SOURCE_INTEGRITY_RECONCILE`, `MAINTENANCE_RECONCILE`, and v12→v13 migration require this closure whenever they publish a map or map receipt. Their existing failure transition owns any gate.

An incomplete idle project whose current receipt is not a valid closure reports `map_review_upgrade_required` and cannot enter `WINDOW_PLAN`. An already active window may finish against its frozen source, but its next map publication must pass this protocol. A completed project remains immutable and read-only. Never rewrite legacy project bytes merely to upgrade the receipt.
