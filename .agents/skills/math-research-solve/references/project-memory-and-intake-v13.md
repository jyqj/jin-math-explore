# Project memory and route review v13

Authoritative causal memory items use `math-research-memory-item/v2`. In addition to the established scope and trust fields, a promoted result records `method_overview`, `parameter_definitions`, `method_spine`, `reusable_structures`, `bottleneck_effect`, `cannot_imply`, and evidence pointers. The overview identifies the method family, baseline, project modification, and high-level mechanism; parameter definitions explain the meaning and selection role of every nonstandard symbol used in the summary. Unknown legacy values remain `review_required`; do not infer them from general mathematical knowledge.

Do not treat an unsolved terminal objective as a reason to discard verified mathematics. An attempt records a proposed `result_map_role` in its reconciliation package; only `window_reconciliation` may promote the conclusion to memory and finalize that role. Use `milestone` when it changed the global project situation or route ordering; use `standalone_result` when the theorem, construction, recurrence, estimate, or impossibility boundary has independent reuse value; use `route_local` when it matters only inside one route history. This classification changes visibility, not mathematical truth or evidence grade. A standalone result must preserve its exact scope, relation to the terminal objective, reusable value, and non-implication boundary.

The authoritative `route_review` uses `math-research-route-review/v2`. It records each route's proof object or missing proof object, mechanism, targeted bottleneck, evidence status, obstacles, failure boundary, reopen condition, comparisons, and reranking conditions. `new_math_performed` must be false: review organizes existing evidence and does not create new mathematics. `why_now`, selected route, and alternative choice belong to a fresh attempt-local `route_decision` made during window planning, not to the review and not to the closed research map.

The map and frozen cognition may quote or summarize these records, but they may not be the first place where causal claims appear. During window reconciliation, promote evidence and write authoritative memory/review before rebuilding the map. A missing causal field blocks the affected route proposal/decision with `review_required`; it does not authorize the Host to invent a reason or preselect the next window.
