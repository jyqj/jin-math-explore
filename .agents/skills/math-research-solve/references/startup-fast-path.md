# Startup fast path v5

Use `scripts/invoke_math_research_startup_v5.ps1` as the first classifier for every project-directory invocation. It is strict, duplicate-key rejecting, DateKind-string-preserving, and **read-only**. It never launches research, changes a counter, creates a Goal, dispatches a worker, or authorizes execution.

New runs use Contract v10 under the current product Goal task. Startup v5 validates v10 directly and delegates v3-v9 to Startup v4 and the frozen earlier classifiers. `Startup Router v2`, `Prompt v7`, and earlier bundles are legacy-only labels. Startup does not rely on isolated `codex exec` Goal persistence.

## New v10 fast path

For `math-research-project/v10`, startup validates the current state, event tail, manifest, ticket, continuity capsule, active route card, optional strategy action, counters, and current artifact hashes. It returns `v10_ready` with the current capsule and route pointers. Read the capsule first, then load every complete artifact it names; do not substitute summaries.

If `project.json` is absent, return `fresh_project_slot`. For an older schema with no migration marker, return `delegate_startup_v4` and invoke the frozen versioned classifier. Never upgrade a project in place. A v8 project with a valid create-new `state/migration-freeze-v10.json` returns `v8_migrated_frozen`; startup verifies the unchanged v8 head, resolves the sibling successor, and reports whether its v10 head is ready. It never delegates that archive back to a writable v8 path.

The current task must still call `get_goal` freshly before any mutation. Startup's `GoalStatus` parameter is advisory and never authority.

The remaining sections document the delegated v3-v8 classifier and are loaded only for those historical projects.

## Closed input surface

Pass only:

- the canonical project directory;
- the freshly observed current-task Goal status as advisory input.

Do not pass caller-selected executable paths, expected IDs, hashes, prompts, models, budgets, routes, or commands. Startup resolves fixed project-relative files itself, rejects path escapes and reparse-point ambiguity, and returns one classification plus bounded model-read pointers.

`cancelled` is represented as `none`. The script cannot prove Goal state; the model host must call `get_goal` again before every lifecycle mutation.

## New v8 project state

For v8, startup may strictly read:

- `project.json` as the single authoritative head;
- the generation-unique `active_checkpoint.path` and `goal_host_state.path` whose hashes/control generations are recorded in that head;
- the exact contract/run files named by those records.

New v8 heads require exact schema `math-research-project/v8` and one immutable generation directory such as `state/generations/g0001/{checkpoint.json,goal-host-v8.json}`, where checkpoint schema is exactly `math-research-checkpoint/v8` and the numeric generation equals `control_generation`. Candidate generations are non-authoritative until, after the fresh Goal gate, `scripts/commit_math_research_head_v8.ps1` names both files in the cooperative guarded final `project.json` head transition. A legacy schema (including schema 1) remains legacy/read-only even if v8-looking pointer keys were appended; it uses fixed historical paths only for classification. Fresh genesis is allowed only when `project.json` is absent. Any existing non-v8/pointerless/empty head receives only a terminal or fail-closed diagnostic classification; this release has no empty-archive activation shortcut.

It cross-checks project ID, contract path/version/hash, run ID/path/status, problem hash, Goal binding, monotone counters, current ticket, and the completion flags, which are valid only as both false or both true. Ticket classification follows lifecycle plus `source_event`, not run status alone: `source_event=null` is an initial solver ticket and startup deep-compares its exact frozen inner content to the selected Contract initial-ticket machine-block member plus the counter snapshot; the builder-created instance is a `preparing` seed and must never be dispatched. A derived ticket has a non-null state `source_event` pointer to an exact `math-research-ticket-event/v8` that one-way binds ticket path/hash, role, inputs, dependencies, Contract/run, and issuance counters. It is not required to equal an initial Contract member, but needs the same full schema/permission/cap validation. `ATTEMPT_START` must replace the seed with a newly frozen active derived solver ticket whose state pointer, ticket envelope, and ticket event all bind the post-start counters; dispatch occurs only after that generation is activated and read back. A verifier is derived only, has nonempty dependencies, and has exactly one additional `candidate_artifact={path,sha256}` equal to exactly one input artifact. Only closed/terminal state may use a null current-ticket pointer. The ticket file contains neither its own hash nor `source_event`. Cycle policy has exact nonempty unique `allowed_worker_tools` and positive `max_ticket_tool_calls`/`max_ticket_output_bytes`; ticket tools are a unique subset and cannot name Goal/control/dispatcher/launcher/lease/`exec` or retired routes, and caps cannot exceed policy. A next `ATTEMPT_START`, whether or not it would hit the interval, is admissible only when the old counters satisfy `attempt_count + 1 <= attempt_budget` and `total_round_count + 2 <= total_round_budget`, preserving one mandatory terminal-audit round. The strict v8 `host_goal` object has exactly `thread_id_available`, `thread_id`, and `objective_raw_sha256`; the first two are `false`/`null` when no stable ID is exposed. `goal-host-v8.json` is ordinary hash-bound advisory state, not a signature, lease, capability, or Goal attestation.

Startup also validates every `ATTEMPT_END.referenced_artifacts[0]` as an exact nine-key `math-research-attempt-outcome/v8`: `schema,project_id,contract,run,attempt_id,outcome,candidate,verifier_completion,completed_at_utc`; the closed outcome is `candidate_found|no_candidate|inconclusive|failed|awaiting_input`. `candidate_found` must close the current derived verifier ticket and cross-bind the same immutable candidate, verifier ticket ID, Contract/run, and exact PASS verifier result/completion. Verifier schemas contain no attempt ID: outcome `attempt_id` is mechanically checked only as a safe ID distinct from the current verifier ticket ID, while the Attempt-record relation is a Host-maintained, unmechanized residual. Its pre-audit `completion_candidate` may be headed only by that `ATTEMPT_END` or an outcome-preserving `HOST_REBIND`, and the next research transition is terminal `AUDIT_START`. The exact cycle-audit plan keys are `schema,project_id,contract,run,audit_kind,candidate,snapshot,active_ticket,tickets,started_at_utc`; plan/summary/reports share the same candidate, with terminal equal to the locked outcome candidate and scheduled/early null. A simultaneous interval/final-attempt gate stays due but terminal audit has priority and its `AUDIT_END` clears it once. Only all-PASS terminal evidence yields `goal_host_completion_ready_to_publish`; terminal non-PASS cannot reach `COMPLETION_READY`. Separately, a paused head permits only `RESUME` or an exact resume-capsule-preserving `HOST_REBIND`; `CHECKPOINT_COMMIT` and every other next event are invalid.

Possible read-only plans include:

| Classification | Meaning | Model action |
|---|---|---|
| `fresh_project_slot` | Exact target does not exist | Under an active current Goal, initialize Contract v8 through the model/file protocol |
| `v8_migrated_frozen` | A valid additive migration marker binds this exact v8 head and one sibling v10 successor | Keep v8 read-only; recover the exact prepared migration plan if the successor is absent, otherwise continue only in v10 |
| `partial_project_tree_recovery` | Some required project records exist but do not form a valid state | Diagnose read-only; do not initialize over it |
| `goal_host_ready` | Cross-file v8 state identifies a ready frozen ticket | Fresh `get_goal`; if it is the `source_event=null` preparing seed, first publish/read back `ATTEMPT_START` with a new post-start-counter-bound derived solver ticket, and dispatch only that derived ticket |
| `goal_host_resume` | Cross-file v8 state identifies one interrupted lifecycle point | Fresh `get_goal`, then resume exactly that point |
| `goal_host_audit_due` | A scheduled, interrupted, or terminal audit is the unique next lifecycle point | Fresh `get_goal`, then run/resume only that frozen audit |
| `goal_host_completion_ready_to_publish` | A terminal cycle audit is fully verified but durable completion is not yet published | Fresh `get_goal`, then publish `COMPLETION_READY` only; no new research |
| `goal_host_completion_pending` | Both completion flags are true; project/head state is permanently read-only | Fresh `get_goal`; only active/matching may call `update_goal(status=complete)`, with no project write; other non-active states remain pending read-only |
| `goal_host_closed_review` | Run is closed/superseded, or product Goal is complete with durable completion flags | Read-only planning only; this release has no executable v8 `RUN_SUCCESSOR` transition |
| `goal_continuity_terminal` | Legacy state records failed Goal continuity | `stop_no_retry_preserve_run` |
| `goal_host_state_invalid` | v8 advisory state is absent, malformed, or cross-file inconsistent | `fail_closed_read_only_diagnosis` |
| `project_identity_invalid` | Project/checkpoint identity conflicts | `fail_closed_read_only_diagnosis` |
| `legacy_execution_unsupported` | No safe v8 action exists for the legacy state | `fail_closed_read_only_diagnosis` |

The names `goal_host_ready`, `goal_host_resume`, and `goal_host_audit_due` are plans for the model host, not commands executed by the script.

## Legacy terminal classification first

Before any compatibility diagnosis, inspect the legacy primary and, when needed, backup state with strict JSON parsing. A self-consistent record may authorize only the safe no-op terminal fuse. Return `goal_continuity_terminal` when the state records:

- latest segment status `goal_continuity_failed`;
- exact marker `MATH_RESEARCH_GOAL_MISSING_OR_MISMATCHED`; or
- failed child Goal continuity together with `persistence_verified=false`.

The safe action is always `stop_no_retry_preserve_run`. Do not infer resumability from checkpoint `preparing`, a human note, an outer active Goal, or a stale bootstrap marker. Do not delete, rewrite, migrate again, or retry the child.

All Prompt v3-v7 Goal bindings are retired, including bindings in apparently nonterminal legacy records. Startup's terminal or unsupported action always remains a stop/no-op for the old run.

## Separate additive successor gate

Startup does not create or activate a successor. After the old-run no-op, the model Host may separately prepare the one prescribed legacy-to-v8 Contract/run only when the user has explicitly created a new active Goal for the same project and a hash-bound effective predecessor envelope normalizes to the same target/domain/quantifiers/dependencies/assumptions/completion, model/reasoning, privacy/external effects, and agent/runtime/attempt/audit/round/cumulative ceilings as the new v8 Contract, without permission or resource expansion. Equality is modulo one mandatory safe contraction: legacy child-Goal/launcher/dispatcher/lease/migration/control-receipt authority is retired and mapped to direct-current-task/v8 + bounded collaboration + the guarded head helper. It is not retained as executable authority. A new `/goal $math-research-solve <same project> continue until proved or disproved` supplies launch intent for that normalized same-target envelope; do not ask the user to repeat confirmation, hashes, or commands. Any research-semantic difference, non-control permission difference, expansion, unresolved normalization gap, or additional Contract/run transition beyond that prescribed `LEGACY_SUCCESSOR` is planning-only/read-only pending a separately implemented and authorized `RUN_SUCCESSOR`; confirmation alone is insufficient.

The model Host must first determine from the user request and frozen problem/quantifiers that the current Goal is a same-target, nonexpanded continuation. No script can prove semantic equivalence of arbitrary natural-language Goal text. After a fresh active-Goal check, the Host invokes `scripts/build_math_research_legacy_successor_v8.ps1` through `math-research-solve.script.build_math_research_legacy_successor_v8`, passing mandatory `-ProjectDirectory`, `-GoalObjectiveRaw`, and `-GoalObjectiveSha256`, plus `-GoalThreadId` only when the platform exposes a nonempty stable ID. `GoalObjectiveSha256` is SHA-256 of the exact raw objective's UTF-8 bytes; the builder uses that text only for the external host binding and mechanically preserves predecessor semantic-section hashes/current effective configuration. Optional `-DryRun` performs validation/inventory only. Optional `-OutputDirectory` must be a distinct, absent, non-nested directory and produces a byte-for-byte archive copy before staging; without it, staging is additive inside the same project. In every mode the builder is Goal-agnostic and never replaces `project.json`.

The exact build-result schema is `math-research-legacy-successor-build-result/v8` with keys `schema,built,dry_run,reason,detail,source_project,target_project,source_project_tree_sha256_before,source_project_tree_sha256_after,expected_old_sha256,expected_old_control_generation,expected_new_control_generation,candidate_head_file,candidate_head_sha256,effective_envelope,migration_map,inherited_artifact_count,trust`. Require `built=true`, either `reason=staged_successor_ready_for_goal_gated_commit` or the idempotent recovery reason `reused_staging_ready_for_goal_gated_commit`, matching old/new generations and hashes, and `trust=staging_only_strict_self_consistency_no_hmac_authenticity_not_goal_authorization`; no result member proves Goal authority. The builder stages a deterministic `state/build-intents/gNNNN.json` (`math-research-legacy-successor-build-intent/v8`, protocol `staging-only-legacy-successor/v8`) with exact keys `schema,builder_protocol,project_id,predecessor_project_head_sha256,predecessor_control_generation,control_generation,goal_host,target_project_directory_name,predecessor_inventory_sha256,generated_paths,created_at_utc`. It write-or-verifies every staged byte, uses a flush plus atomic no-overwrite publication, and a retry may fill only missing bytes; a mismatch fails closed. A preactivation staging retry accepts only the same raw Goal objective hash; a different Goal raw hash is fail-closed, and there is no live staging authority. The builder fully replays legacy ledger files `00000000.json` through the checkpoint head with no gaps/extras, exact envelope/payload hashes, run/sequence/previous-hash chain, and closed legacy event rules; replayed five counters must equal the manifest checkpoint/head. Compatibility/control receipts bind the matching replayed ledger prefix (`head_sequence`,`head_payload_sha256`) rather than falsely requiring the current head, so later legitimate progress is preserved. The builder is the dedicated exact-schema/source validator for the effective-envelope and mapping artifacts. The head helper/startup later validate their project-event raw pointers/hashes generically, not through a duplicate schema-specific parser, so do not bypass the production builder with a hand-assembled candidate. The builder snapshots the exact old `project.json`, preserves every predecessor byte, freezes the effective predecessor envelope, explicit retired-control mapping, complete inherited artifact index, and independent cumulative counter/budget baseline, then stages `state/successors/gNNNN.json`, new `RUN_GENESIS`/host binding, and generation checkpoint/state. The new Contract binds the effective-envelope and mapping artifacts by path/hash, and the first `LEGACY_SUCCESSOR` project event lists both raw pointers in `referenced_artifacts`. The lineage file remains the `LEGACY_SUCCESSOR` record and its exact key set does not change. It remains non-authoritative until, after another fresh Goal gate, `scripts/commit_math_research_head_v8.ps1` performs the cooperative guarded activation transition (expected-old equals the snapshot hash/generation). A crash or mismatch before it leaves old pointers unchanged and all new files unreferenced. Later v8 heads preserve the activated lineage pointer and its activation generation byte-for-byte; they never recompare the predecessor snapshot to a later expected-old. Authority comes from the freshly active current Goal, never an old HMAC/receipt or either helper. This is a new run continuing the same archive, not a legacy Goal Resume.

Any malformed, mismatched, future-dated, path-escaping, or identity-conflicting input fails closed to read-only diagnosis. Hash consistency is not described as cryptographic signature verification.

## Goal gate

Startup must preserve terminal and diagnostic classifications regardless of the advisory Goal status. For a plan that would later cause research or authoritative writes, `none`, `paused`, `blocked`, `complete`, or `unknown` blocks that later action. The current task must perform a fresh `get_goal` and require the recorded active binding before proceeding.

A new task cannot inherit ownership from the path. An existing v8 run may use the special rebind gate only after explicit user revocation of the old binding and authorization of the new Goal/rebind: fresh new Goal active, no unfinished commit, and unchanged Contract semantics/permissions. User revocation is sufficient; never query the old task. The new Host stages one exact-schema `HOST_REBIND` whose `prior_host_binding` equals the old head and whose `retirement` records `authority=user-explicit-revocation` plus a nonempty reason, increments `control_generation`, and performs the cooperative guarded head transition last. No separate `HOST_RETIRE` exists. The new raw hash need not match the obsolete binding. A legacy run never rebinds; it can only receive the separately authorized additive successor above.

When a v8 checkpoint durably records `completion_ready=true` and `pending_goal_update=true`, startup returns `goal_host_completion_pending` unless the advisory Goal is already complete, in which case it returns `goal_host_closed_review`. The project/head is permanently read-only: never clear flags, resume, audit, publish, or rewrite closing state. The current task calls `get_goal` freshly; only an active/matching result may lead directly to `update_goal(status=complete)`, with no project mutation. Any other non-active Goal remains read-only pending.

## Legacy compatibility labels

The files `scripts/invoke_math_research_startup_v1.ps1` and Startup Router v2 remain byte-preserved historical entries. Prompt v3-v7 remains frozen under its original records. Startup v3 may classify those records for preservation, but this v8 path does not promise that any historical Goal-owning child can continue.
