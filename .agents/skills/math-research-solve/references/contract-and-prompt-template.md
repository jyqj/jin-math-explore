# Legacy Prompt v6 template compatibility notice

> [!CAUTION]
> Deprecated and inspection-only. This filename must never generate, confirm, authorize, or launch a new run. Do not ask a user to repeat a confirmation phrase, hash, or command from historical material.

New contracts use [the Contract v8 template](contract-and-prompt-template-v8.md), Startup Router v3, and the direct-current-Goal-task protocol. Prompt v7, Startup Router v2, and the launcher/canary bundle are legacy inspection labels, not a New or Resume route.

An existing Prompt v6 run is preserved only in its original recorded project `runs/<run-id>` directory with its original thread, contract, counters, executable pin, and frozen approval policy. This file, its manifest, and its legacy HMAC are not authority sources for that run. Startup v3 may classify its manifest for a read-only terminal fuse, but it never infers or executes Resume authority. Contract v8 now implements the only continuation exit: under an explicitly user-created new active Goal, `LEGACY_SUCCESSOR` may add a new v8 run in the same project while keeping every legacy byte read-only and inheriting all artifacts, routes, failures, audits, counters, and budgets; it is never a legacy Resume.

Legacy `rollover=false` / `rollover=never` forbids automatic or same-run rollover only. It does not forbid a user-explicit new Goal plus the prescribed additive v8 successor under the normalized same-target/nonexpanded research envelope; that successor inherits every old consumption counter and must retire old child-Goal/launcher/dispatcher/lease/control-receipt authority in favor of the narrower v8 current-Goal path. Any other envelope difference is planning-only/read-only pending an implemented `RUN_SUCCESSOR`; confirmation alone cannot activate it.
