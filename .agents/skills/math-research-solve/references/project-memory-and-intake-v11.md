# Unified project memory and external intake

Every memory item records: class, statement, origin, trust state, evidence, what it permits, what it does not imply, and an exact reopen condition.

Classes are verified fact, verified failure boundary, bounded negative, attempted with difficulty, conditional result, open bridge, source claim, and known pitfall. Origins are `internal_attempt`, `external_intake`, or `legacy_project_import`; only the first requires attempt/ticket identity.

External material follows this chain:

`registered_unverified -> reproduced -> independently_verified -> promoted`

Reproduction freezes raw hashes, executes declared reproducible code, and records exact domains and failures. Independent verification must inspect the frozen reproduction and use an independent implementation where the claim is computational. Only an exact scoped verifier `PASS` can promote a verified fact, failure boundary, or bounded negative. A failed or incomplete reproduction becomes `attempted_with_difficulty`, never an exclusion theorem.

Do not promote an archive wholesale. Maintain a claim inventory and separate claims by evidence. Keep finite searches finite. Preserve incomplete scans with their actual stopping boundary and tool requirements. Distinct numerical constants remain distinct until a proof identifies them.

Before planning a research route, read the full promoted memory, bounded negatives, attempted-with-difficulty records, conditional claims, open bridges, known traps, tool requirements, and latest route review. External rounds never increment internal attempt counters.
