## 从上一轮接上了什么

第 16 轮给出了“已有匹配时”的删除、位移和归一化误差。本轮将匹配本身
变成有限输入上的构造问题：程序返回**保持保留总质量的最优代理代价匹配**，
或者返回各质量配额的割证书；原轨道不拆分，不把双零点变成简单点。

具体增量是区间 Hall 缺额公式、带深度权重的拥挤下界、含强制重数裁剪的
线性删除代价上界，以及对简单／非简单轨道配额逐一枚举的有理最小费用流。
结果附残量网络势函数或割证书。`verify` 不调用求解器，即可核对最优性或
不可行性，并重新计算删除、位移、质量及原简单点计数。

最优性仅针对明确定义的**保守代理目标**，不是实际算子误差的最优性。
代理目标大，也不能据此声称实际算子低代价匹配不存在。

## 留下的反例与边界

质量不同的轨道按位置顺序分配可能不是最优：一个精确例子中位移代价从
`417/100` 降至交叉匹配的 `257/100`。另有例子说明，Hall 可匹配不等于能
保持指定保留总质量。一个总质量均值一、简单比例 `2/3`、轨道数仅占容量
`5/6` 的互异实点族，仍然有线性数量的局部拥挤和不消失的删除代价。
这些反例没有满足真实零点的全部条件，不能称为黎曼猜想反例。

[完整推导](proof.md) 区分几何不可行、代理代价不够小、实际算子误差和
真实来源定理；[结论清单](claims.json) 记录量词及不能推出的内容。
[来源与恢复记录](source-scope.md) 保留上一轮 commit 和经典算法归属。

## 复现和使用

```sh
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python check_matching.py --samples 120 --output /tmp/rh17-validation.json
python check_matching.py --check-package
```

求解器仅依赖 Python 标准库；数值回归还需要 NumPy、mpmath。一个输入例子：

```json
{"Q":3,"margin":"1/16","radius":"1/4","depth_cap":"1/2","weights":["1","1","1"],"orbits":[{"x":"1/2","a":"0","mass":1},{"x":"3/2","a":"1/2","mass":2}]}
```

```sh
python matching.py input.json --output certificate.json
python matching.py input.json --verify certificate.json
```

数值须用整数或有理字符串；程序拒绝把浮点当作精确数据。`Q` 是预先指定的
目标单胞数，也必须等于最终保留质量。`margin` 是闭合内缩单胞边界，
`radius` 是最大位移，`depth_cap` 超标轨道必须删除。`weights` 分别惩罚
质量加权平方位移、保守删除代价和原简单点删除数量。

[实际输出](validation.json) 包含三个完整示例证书；[计算记录](computation-record.json)、
[交接](computation-handoff.json) 和 [哈希清单](checkpoint.json) 覆盖本轮工件。
